### 为什么要改

联调安阳样例 `docs/samples/01-anyang-zhengwu-yunwei.pdf` 时发现：

1. **`auto` 误推 MinerU**：94 页「原生复杂 PDF」被推荐远程 MinerU；未配置 `MINERU_API_TOKEN` 时任务失败。  
2. **章节过碎**：pdfplumber 输出 `## 第 N 页`，再加宽松标题检测，约 **716** 个 section，大量空壳／页标题。  
3. **B07 尚未起步**：方案要求「六类要求 + 可定位证据」，需要可跑的草稿链路，而不是先换 PostgreSQL。

### 改动总览

| 主题 | 状态 | 要点 |
|---|---|---|
| A. `auto` 解析策略 | 已合入 | 有可用文字层 → 默认 `pdfplumber`；扫描件才推 MinerU |
| B. 章节切分降噪 | 已合入 | 去掉页标题；收紧标题启发式；合并页碎片；补 page 元数据 |
| C. B07 规则抽取草稿 | 已合入 | Schema／仓储／API；规则抽六类 + evidence refs |
| D. 文档与测试 | 已合入 | 改动说明、B07 草稿、策略／切分／抽取单测 |

**未做**：MinerU 付费联调、B07 前端确认台、LLM 精抽、B08 PG 迁移。

### 详细说明

#### A. 解析策略

**文件**：`backend/bid_agent/parsing/strategy.py`、`document_parser.py`（`_normalize_parse_method` 委托 strategy）、`tests/test_parse_strategy.py`、`README.md`

| 画像 | 旧推荐 | 新推荐 |
|---|---|---|
| `simple_text_pdf` / `native_text_pdf` | 页数 ≥30 常走 MinerU 并行 | **`pdfplumber`** |
| `mixed_pdf` 且样本页文本够用 | MinerU | **`pdfplumber`**（警告：图片字可能漏） |
| `scanned_pdf` / 无可用文本层 | MinerU | **仍为 MinerU** |

用户手动选择的 `parse_method` 不变；空／`auto` 统一走 strategy。

#### B. 章节切分降噪

**文件**：`backend/bid_agent/parsing/document_parser.py`、`tests/test_section_split.py`

1. pdfplumber 只写 `<!-- page:N -->`，不再写 `## 第 N 页`。  
2. 收紧 `_detect_heading`／`_looks_like_heading`。  
3. 新增 `consolidate_bid_sections`，传播页码。  
4. 删除重复的旧版 `_parse_pdf_with_pdfplumber`。

安阳样例（pdfplumber）：section 约 716→295；「第 N 页」标题 94→0；`page_start` 全覆盖。  
**注意**：旧解析结果不会自动重算，需重新提交解析任务。

#### C. B07 结构化要求草稿

**文件**：`schemas/requirements.py`、`services/requirement_extract.py`、`repositories/requirements.py`、`api/routes/requirements.py`、`main.py`、`platform.py`（migration v2）、`rule_extractor.py`（中文项目编号）、`docs/implementation/b07-draft.md`、`tests/test_requirement_extract.py`

**API**

```http
POST /api/v1/document-versions/{version_id}/requirements/extract
GET  /api/v1/document-versions/{version_id}/requirements?category=overview
POST /api/v1/requirements/{item_id}/review
```

重抽只覆盖同 extractor 的 `draft`，保留已确认条目。  
安阳实测约 224 条草稿；概览字段可用，技术类噪声偏大。
